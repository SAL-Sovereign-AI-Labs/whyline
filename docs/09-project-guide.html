Whyline: every AI-written line keeps the prompt that caused it

git blame tells you who. Whyline tells you why: the Bob prompt behind a line, whether a human changed it since, whether it was meant to be temporary, and what a release is made of. One command line tool, zero dependencies, nothing leaves the laptop.

1Zoom out: the whole thing on one screen

A loop. The top half records automatically while people work in Bob. The bottom half answers questions from what was recorded, and feeds one of those answers back into Bob.

In one line: Bob writes, a free hook records, a commit seals a git note, and every answer reads that note. New work only adds readers (unreviewed, bom, report). The recorder is not touched.

Why does demo/ build a repo instead of containing one? Whyline's records live inside a repo's own git data. A script that builds a fresh repo gives the same starting point on every laptop and every video take, and the payloads it replays are real Bob hook data.

6Designed for more agents, without touching the core

No cross-agent hook SDK exists (docs/07). The credible tools keep one adapter per agent, and so do we. Each adapter answers the same six questions; everything else reads normalized events.

Contract tests in cli/test/agents.test.js run against every registered adapter. The step-by-step guide is docs/08-adapters.md. Rulesync can write our hook command into ten agents' native configs later; that is an installer option, not a capture layer.

7A real user story, six scenes

1 · Monday, Bob IDEDeveloper asks for a mock payment gateway "until payments-v2 lands". Bob writes the file.
hooks → capture → session.jsonl
2 · Monday, commitLines arrived unchanged, so they are "ai". Words "mock" and "until" make item L-… with condition no_references.
post-commit → whyline commit → git note
3 · Three weeks laterA teammate runs whyline why on a line and reads the original prompt and the item.
git blame → note → answer
4 · payments-v2 dayThe merge removes the last use. check says due. Bob's next session opens with "1 item due". In whyline-remover: "remove L-…". Evidence, tests, approval, commit.
post-merge → check → Bob
5 · Friday, team leadwhyline unreviewed: AI lines nobody edited since, worst files first, with coverage.
notes + blame + coverage
6 · Release daywhyline bom v0.1.0..HEAD for the numbers and whyline report for one page everyone can open.
notes → JSON + HTML

8Do not change

Recorder and commit stepcapture, commit, patch, session. New features only read what they produce.
Note format v1Every reader depends on it. Add fields, never rename.
Hook identityThe installer recognises a Whyline hook by script path plus subcommand (whyline.sh capture), so flags may change; the script name may not.
Hooks never failcapture, commit, session-start always exit 0.
check exits 2 when dueThe merge hook and the Bob mode rely on it.
Removal pathEvidence, tests, then Bob's own approval. Never auto-delete.
Zero dependencies, no networkAnything that talks to GitHub is opt-in.

Check first (Bob IDE)

Hooks in the IDELive tests used Bob Shell. Confirm the IDE fires the same payloads.
Cost location in the IDEShell keeps it in ~/.bob/db/bob.db. The IDE may not. If absent, cost is null.
apply_diff response in the IDEThe fixture is rebuilt from a Shell capture. If the IDE differs, ranges become approximate. Capture one real example and add it as a test.
Whyline on the PATHGit hooks only run when whyline is found. Use npm link during development.
No squash merges in the demoSquash drops notes on the squashed commits.
